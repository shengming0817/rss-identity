# #2333 / #2358 本地账户 authority

当前决定：账户 Rust API 与 `identity-admin` 是 I03 已有入口；#2358 将初始化和管理员应急恢复收敛为独立维护身份执行的单条命令。登录/session HTTP 属于 #2334，管理 HTTP/UI 属于 #2337，装配与 T3 属于既定后续 owner。验证结果以 PR 实际运行记录为准。

## 唯一业务 owner

`rss_identity_core::account` 持有账户值、变更规则、秘密和 KDF；`rss_identity_postgres::Authority` 持有账户事务；#2337 已用明确的 session-only 操作替换 create_account/change_account。initialize/recover_administrator 仍属于维护身份。当前管理入口见 I07 ADR。

账户 key 为 `(tenant, principal)`。登录键、口令、启用状态、管理员资格、认证 epoch 均在租户内持久化；成员关系有独立状态和 epoch。不共享跨租户口令，不按登录名或邮箱关联身份。登录键为至多 128 字节的 ASCII lowercase，拒绝首尾空白和控制字符。

AuthenticationCandidate 不可复制/序列化、无公共构造器，绑定 authority 数据库身份、账户/成员/凭据版本及原截止时间。普通账户快照不是认证证明。所有日常写入先取得 tenant guard，再复核候选和最新状态；最后可用管理员谓词为同租户 enabled、administrator、active membership 的本地账户。

## 唯一维护边界

`AuthorityProfile::Runtime` 使用 `identity_account_runtime`，负责日常认证和账户管理；`Maintenance` 使用 `identity_account_maintenance`，只暴露初始化和管理员密码恢复。两种身份互斥，连接时检查实际有效权限，不把枚举值当数据库授权。

维护数据库凭据由部署 owner 保管，仅注入受控维护任务，不放入日常服务的可读文件、环境或共享 secret mount。远程运维执行须经过部署侧授权；CLI 本身不提供远程入口。两种身份不是双人审批。Runtime 仍有日常账户直接写权限，因此不承诺抵御其数据库凭据失陷后的直接改库；维护身份或宿主机失陷也不在该隔离保证内。RLS 约束事务租户，不宣称可抵御持有数据库凭据者任意设置租户上下文。

不再签发或消费临时授权，不存在授权表、授权秘密文件、过期/重签/重放机制，也不增加恢复 token、预读快照或 CAS 协议。Maintenance 无 attempts 权限；日常密码验证保留共享限流。密码 KDF 的资源上限和操作期限同样适用于维护。

## 初始化与恢复

初始化只允许部署完成一次。`bootstrap_tenant IS NULL` 表示未初始化；非空同时表示已初始化及其租户。事务先锁 deployment，再锁 tenant guard，原子写入首个管理员、成员关系、bootstrap tenant 和 initialized 安全事件。数据库触发器禁止初始化后清空/更换 tenant 或改写 authority ID，不另存重复布尔状态。

恢复在锁外计算新口令哈希，事务内取得 tenant guard，读取明确 `(tenant, principal)` 的当前状态，确认仍是管理员后调用 `AccountState::recover()`。只更新 password_hash、auth_epoch、credential_version，保留 enabled、administrator、emergency、membership 状态及成员 epoch。不以恢复自动启用应急账户或授予管理员资格。

合法并发恢复按 tenant guard 串行化，最后提交的密码生效，epoch 每次递增。并发降权先提交则恢复被拒绝；并发禁用或成员停用不会被恢复覆盖。恢复后旧 AuthenticationCandidate 失效；本项不据此宣称会话系统或 MFA 恢复已实现。

Maintenance 仅有账户/成员 SELECT、INSERT，以及账户密码/认证 epoch/凭据版本的列 UPDATE；读取成员依赖已持有的 tenant guard，不为行锁授予成员 UPDATE。Deployment 仅允许更新 bootstrap_tenant；Runtime 无该写权限。两者各持有所需 guard 和 RSS 事务/Outbox 权限，不授予 owner、schema CREATE 或高权角色。

## 原子事件、期限与失败

唯一私有事务 helper 复用 RSS PgRuntime，账户修改与安全事件同事务。事件 action 为初始化、恢复及有明确方向的日常账户变化；每条事件携带完整非秘密后状态，epoch 至少为 1。移除仅用于票据签发的空 state 分支。维护事件 actor=null 表示部署身份操作，不伪称可追溯到具体人工操作者；人工操作归属由受控运维入口记录。

只有确认提交才返回账户结果并输出主体/epoch；NotStarted、RolledBack、RollbackFailed、CommitUnknown 和 Fenced 保持原语义，不自动重试。不输出原始 SQL、口令、哈希、provider 错误或配置值。未知结果先由运维核实账户状态/安全事件，不能根据退出码假设已回滚。

Argon2id v19 固定 m=19456 KiB、t=2、p=1，16 字节盐和 32 字节输出。新口令至少 15 个 Unicode 字符且至多 1024 UTF-8 字节，不 trim/truncate。PHC 在 KDF 前校验；秘密和哈希 Debug 脱敏并在释放时清零。4 个进程共享 KDF permit 由实际 blocking 任务持有，取消等待不提前释放。

日常密码验证独立提交尝试预算：目标 5 次/15 分钟、来源 30 次/5 分钟；known/unknown 同样计数，失败不退还，不永久禁用账户。最多 10,000 个有效或待清理键，每次最多清理 128 个过期键。来源由可信 adapter 提供，不信任客户端 forwarded header。这些值不是生产 SLO。

## 破坏性变更

I03/#2358 阶段用户确认现有数据均为可丢弃开发库，初始安装为 schema version 2；当前 I04 的 version 3 与会话扩展由 [#2334 ADR](202609080900-2334-central-session.md) 替代；无增量迁移、旧命令别名、兼容角色或旧 schema 分支。旧库连接明确拒绝，开发环境停用旧进程后重建专属库和角色；不自动清库，不用 CASCADE 删除未知角色依赖。

事件仍为尚未发布的 account security V1，直接收紧 action/state schema，schema digest 随之变化；旧开发库与其 Outbox 一并重建，不混用旧事件和新定义。RSS 固定 Git revision、wire 身份协议及 AuthenticationCandidate 契约不变。

I03 阶段连接探测按六张表、四张 tenant RLS 表（I04 扩展见上述 ADR）逐项核对有效表/列权限，包括 PUBLIC、继承和 GRANT OPTION；schema 版本、唯一约束、RLS 或角色漂移 fail closed；诊断区分 schema version、role、privileges、schema contract，保持低基数且不输出 provider 原文。安装遇到既有同名全局角色直接失败，不静默接纳其它部署的角色。
