# #2333 本地账户 authority

决定：I03 的生产接口为类型化 Rust 账户操作和 `access-admin` 本机工具。HTTP 登录/session 属于 #2334，管理 HTTP/UI 属于 #2337；Hydra bridge、装配和 T3 仍属于既定 owner。此文档说明设计；运行结果以 PR 实际验证为准。

## 唯一 owner 与接口

PrincipalId 是全局不透明 ID。本地账户的 key 是 `(tenant, principal)`；登录键、口令、启用状态、管理员资格、认证 epoch 均在该租户内持久化。成员关系有独立有效性和 epoch。不共享跨租户口令，也不按登录名或邮箱关联身份。登录键是至多 128 字节 ASCII lowercase，不接受首尾空白或控制字符。

`access-core::account` 拥有账户值、变更类型、秘密和 KDF；`access-postgres::Authority` 提供 verify_password、create_account、change_account、issue_authorization、initialize、recover_administrator。候选值不可复制/序列化，没有公共构造器；包含 authority 数据库身份、账户/成员/凭据版本和原请求截止时间。普通快照不构成认证证明。

I02 的公开任意 SQL/字节事件组合接口已由具体业务操作替换，不保留兼容包装。私有事务 helper 仍使用 RSS 的同一 PgRuntime，只有确认提交才释放返回值；确认签发回执字段私有，不允许应用自行构造；不创建第二个事务 owner 或公共 UnitOfWork。账户写后产生关闭的事件枚举，事件字段只包含明确方向/用途的动作、租户、主体、操作者、epoch 及账户变更后状态（enabled/administrator/emergency/member_active/credential_version/membership_epoch；授权签发的 state 为 null），消息 envelope 另持有随机事件 ID/时间。异常不输出原始 SQL/秘密。

认证 epoch 与 RSS 的 storage/tenant fencing 不同。管理员写先锁 tenant guard，再按 ID 排序锁账户，最后检查成员/凭据；禁用、权限或口令变化提升 epoch。所有写失败必须整体回滚。最后管理员谓词为同租户 enabled、administrator、active membership 的本地账户；不存在默认账户/密码。应急管理员显式创建/启用，禁用不会因恢复而自动解除。

## 单次初始化与恢复

部署仅初始化一次，首次签发绑定 bootstrap tenant；初始化状态不可回退。初始化授权替换该部署的旧初始化授权。恢复授权绑定租户、已有管理员、签发时账户 epoch，期限 15 分钟。只保留该目标/用途的当前授权；重签使旧 secret 失效。恢复替换密码并提升 epoch，保留 enabled、administrator 与 membership。

授权是 256 位 CSPRNG opaque secret，数据库仅存 SHA-256 摘要及绑定，不用自包含签名 token。普通数据库身份属于 access_account_runtime，可消费但不能签发/替换授权；独立部署身份属于 access_authorization_issuer，仅签发/重签，不具有账户密码写权限。两者另需各自最小 RSS Outbox/fencing 权限，由装配 owner 配置。

确认提交后，工具才以 create-new/0600 写 secret 文件。CommitUnknown 不写文件、不自动重试；数据库已提交但文件失败/进程退出时，操作者重新签发，旧授权随之作废。文件与 PG 不具跨资源原子性，不回读未知提交来释放旧 secret。不允许通过直接改库恢复账户。

## KDF、尝试与期限

Argon2id v19 固定 m=19456 KiB、t=2、p=1，16 字节随机盐、32 字节输出。新口令至少 15 个 Unicode 字符且至多 1024 UTF-8 字节；不自动 trim/truncate。PHC 格式与参数在计算前检查，秘密/PHC Debug 脱敏并在释放时清零。

进程共享 4 个 KDF permit，超额直接拒绝。permit 由实际 blocking 任务持有，取消等待不释放仍在计算的资源。数据库锁外计算，事务内重新检查版本、状态和原截止时间。未知账户走同成本 dummy KDF；高熵授权摘要核验不使用 KDF，只有授权预检查通过后才为新密码计算哈希。

每次验证先独立提交尝试预算，不因后续错误退还。共享 PG 登录/授权范围预算 5 次/15 分钟，来源预算 30 次/5 分钟；最多 10,000 个有效或待清理键，每次最多清理 128 个过期键，容量不足拒绝新键。known/unknown 同样计数，不永久修改账户 enabled。来源是可信调用 adapter 的输入；本机工具使用固定 local-operator 来源，未来网络入口不能直接信任 forwarded header。这些是初始策略，不是生产容量/SLO。

## 后续消费

#2334 在同一 PG adapter 内增加具体 session issuance 方法，复用事务内账户复核；创建 session 与登录成功事件同事务，提交后才释放 session secret。I03 的密码候选不是“登录成功”。#2336 只能在 Access 确认提交后调用 Hydra，不宣称跨服务原子性。I09 承担应急凭据保管、使用后轮换规程、MFA、备份和恢复演练。

## 内审闭合

core 的 AccountState 只经校验构造并提供只读 getter；纯转换、权限规则、epoch 推进、最后管理员约束及 SecurityAction 均由 core 持有。PG 仅加载锁内事实，调用规则后持久化，不创建第二份 PG 私有领域状态模型。公开快照仍不是认证凭据。

构造 authority 必须通过具体 Runtime/Issuer profile 的存储探测；未知同名集群角色在迁移时拒绝，有效权限与 schema/RLS 漂移在连接时拒绝。事务错误同时保留 settlement 确定性与安全低基数原因，仍不自动重试。

## PR 965 审查修复

未发布 V1 事件直接冻结为 initialization_authorized/recovery_authorized、administrator_granted/administrator_revoked、membership_enabled/membership_disabled 等有方向的动作，不保留旧 action 别名。schema 由 PG adapter 持有；账户创建/初始化/恢复与每条变更携带完整非秘密后状态，发行授权只表达用途与被授权主体/epoch，actor=null 表示独立部署身份授权，而非可追溯的人工操作者身份。T2 断言完整 payload、tenant、domain、route、contract/version、schema digest，禁止凭 Outbox 行数代替内容证明。

权限探测按迁移拥有的七张表（五张 tenant RLS 表、deployment、schema_version）比较每个 profile 的有效表/列权限与精确允许集合，包含继承/PUBLIC 权限与 GRANT OPTION。拒绝额外 UPDATE、TRUNCATE、REFERENCES、TRIGGER、MAINTAIN，不能只拒绝已知敏感字段。

领域拒绝通过事务私有闭合值保留；只有确认回滚后，AuthorityError::RuleRejected 才区分最后管理员保护、generation 耗尽和非法领域状态。认证/普通拒绝仍统一 Rejected。RollbackFailed/CommitUnknown/Fenced 不被领域原因覆盖。探测返回 false/null 才投影 StorageIncompatible；provider 错误原样保留 settlement 与低基数分类。

CLI 在打开配置/连接数据库前检查命令、参数数量和角色，并提供 --help；配置 JSON、tenant、CA、storage identity/epoch、principal/login/password 各用无输入值的诊断。I03 仅保留文件/PG 接缝 T2；真实 binary/config/TLS PG 装配测试从本 PR 移除，由 #2341/T32 的独立 Issue/PR 交付，不宣称本次已证明产品 T3。
