# #2334 中央登录会话

状态：I04 实现决定。T1/T2 的实际命令、结果和源码身份随实现 PR 记录，不表示 UI、Hydra bridge 或生产 binary/config/TLS T3 已交付。

## 一个认证代际、一张会话表

账户 `auth_epoch` 统一表示认证有效性：密码、账户/成员/管理员资格变化、维护恢复和全部退出使旧认证失效。现有 AuthenticationCandidate 持有该代际，签发会话时在同一事务重验，全部退出前验证的候选不能在退出后产生有效会话。不另设 session epoch。

`identity_authority.sessions` 固定 tenant/principal/session ID（PG/HTTP/view/cursor 统一使用 core SessionId，serde/SQL 边界拒绝 nil），保存一个 256-bit 随机 cookie 秘密的 SHA-256 摘要、签发代际、成员代际、认证时间、idle/absolute 期限与当前撤销时间。无 refresh-token 历史、family、重复 active/expired 状态或产品资源权限。只读 SessionView 不是认证证明，AuthenticatedSession 无公开构造/Clone/Serialize，绑定 authority ID、当前凭据和原请求期限；任何后续写入重新核验。

普通会话 idle 30min/absolute 8h，管理员 15min/4h，按事务内账户资格选择。SessionLifetime 在 new/restore 时将类别绑定为私有闭合 SessionClass；renew 只收 now，不能更换类别，恢复校验 absolute 与绑定类别一致。PG 在锁后读取 clock_timestamp；now >= 期限即失效，时间倒退至认证时间前拒绝。HTTP 查询只验证、不延长 idle；HTTP 续期集中于受 Origin+CSRF 保护的 POST refresh，永不延长 absolute。Rust authenticate_session 的活动续期仅供已建立请求保护的可信 adapter 使用。

## 轮换、撤销和提交

刷新只原子替换当前摘要，保留 session ID、auth_time、absolute expiry；旧值与任意无效值同样拒绝，不保存历史来区分重放来源。并发恰一胜出，失败方不能撤销胜出凭据。当前退出设置该行 revoked_at；全部退出只推进账户 auth_epoch，不批量写所有会话。

带有效同租户同主体 cookie 的重新登录，校验 CSRF 后原子撤销旧行并建立新 session ID/秘密。无效或过期 cookie 不阻止新的密码登录；同源校验和专用 JSON 请求头仍必需。账户权限变化使旧会话失效，重新登录按最新权限创建，不提供无重新认证的提权路径。切租户重新登录产生独立租户会话；不会用新租户凭据跨租户撤销旧行。

锁序为 tenant guard → account/membership → session，适用于认证、轮换、撤销与候选签发。会话入口仅锁既有 guard，不尝试 INSERT；创建 guard 只属于显式账户/维护/尝试预算写路径，缺失 tenant 的会话认证直接拒绝。首次按摘要定位后锁内重读。全部退出与刷新竞争时，刷新先提交可使基于旧凭据的退出请求被拒绝；退出成功时后续验证必拒绝。已完成验证的在途操作不追溯取消，调用方不能缓存成功上下文用于新请求。

创建（含替换）、刷新、当前/全部撤销与 `identity.session.security` V1 事件共享现有私有事务结算。账户事件继续使用原契约，不改造成可任意注册的事件框架。session 事件仅 action、tenant、principal、session_id、replaced_session_id 和 epoch。只有 confirmed commit 返回成功和凭据；CommitUnknown、RollbackFailed、Fenced、存储错误与超时不返回凭据、不自动重试。确认提交但丢失响应的凭据无法恢复，用户重新登录；absolute expiry 限制其有效时间。

Hydra 和上游 IdP 状态不属于本 PG 原子事务。协议清理失败不能重新激活 Identity 会话；本项不宣称上游全局退出或下游 Hydra bridge 完成。

## HTTP 边界

接口详见 [wire](../identity-wire-v1.md#中央会话-httpi04)。Cookie 为 __Host-identity-session、Secure、HttpOnly、SameSite=Lax、Path=/、无 Domain；Max-Age 是剩余 absolute 时间，idle 完全由服务端校验。GET/HEAD 不续期且不重复发送 cookie，失败响应不删除或覆盖 cookie，避免并发失败响应覆盖刷新胜出值。

写请求 Origin 必须精确匹配部署配置的 canonical HTTPS origin，不从 Host/Forwarded 推导。首次登录要求 JSON 和 X-Identity-Request: 1，已认证 cookie 写入另校验 X-CSRF-Token。CSRF 是 SHA-256("rss-identity.session.csrf.v1\0" || cookie secret) 的小写十六进制值，使用常量时间比较，与认证摘要域分离，不额外存储；随 cookie 轮换。登录替换先只读验证旧会话，CSRF 通过后才允许活动延长或状态变更。未认证/过期 cookie 可重新登录，不把 SameSite 当作 CSRF 防线。

Router 所有响应 no-store，无 CORS 开放。登录来源必须由实际连接的 Axum ConnectInfo<SocketAddr> 提供，忽略 forwarded headers；TLS、可信反代接缝和真实域名注入属于装配 owner。配置请求预算须在 (0,60s]，body 读取、验证密码、发会话等连续操作共享同一截止点。HTTP 只对入站 JSON body 读取执行取消；一旦进入 Authority，沿用 RSS 事务 owner 的有界执行/commit/rollback 结算，不用另一个 HTTP timeout 丢弃结算分类。体读取超时是 RequestTimeout，事务未确认是 Authority(CommitUnknown/RollbackFailed)，公开均503且不发cookie；不增加宽限重试或后台脱离请求的提交任务。所有接口只产生 Identity 中央会话事实，不冒充产品 wire 的 VerifiedIdentityContext。

会话列表只含当前主体当前租户有效会话，UUID 游标升序、默认 50/最大 100，查询再次验证调用凭据。列表不承担历史审计或保留策略；失效行不影响认证，物理保留与调度由部署 owner 决定，不在请求路径无界清理历史。
