# 文档维护

需求归 product，架构与实施依赖归 architecture，开发操作归 guides，生产流程归 deployment，历史与外部来源索引归 reference，稳定规则归 rules。评审、修复处置和逐次验证结果归对应 PR；文档不保存 PR 实施流水、逐轮验收记录或其链接索引。

长期入口使用稳定名称；ADR 等需要长期维护的独立文档采用 `yyyyMMddHHmm-编号-实际功能或问题.md`。新增文档更新目录导航。需求和验收编号稳定；实质变更说明原因和影响。

源码树保留可复用的验证脚本、测试源码、夹具与必要说明；逐次生成的报告、候选清单、消费者 manifest/lock 和配置副本不默认提交。PR 记录固定 revision、实际命令、结果和未覆盖项；需持久保留的完整输出存入 CI 制品或专用归档，并在 PR 中引用实际可用的位置，不以本地临时路径冒充持久归档。

已提交的旧过程记录通过 Git 历史追溯；历史通过不作为当前版本的验收结果。

需求目标、待决策建议、历史实现、当前实现、测试实现与实际测试结果分别标注。来源引用可定位路径或公开 URL；被本地排除的材料说明恢复方法。Issue 草稿只有取得真实 work item ID 后才标为已登记。
