# 文档维护

需求归 product，架构与实施依赖归 architecture，开发操作归 guides，生产流程归 deployment，历史与外部证据归 reference，评审归 reviews，稳定规则归 rules。

长期入口使用稳定名称；过程记录采用 `yyyyMMddHHmm-编号-实际功能或问题.md`。新增文档更新目录导航。需求和验收编号稳定；实质变更说明原因和影响。

需求目标、待决策建议、历史实现、当前实现、测试实现与实际测试结果分别标注。来源引用可定位路径或公开 URL；被本地排除的材料说明恢复方法。Issue 草稿只有取得真实 work item ID 后才标为已登记。
