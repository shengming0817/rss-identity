# 文档维护

需求归 product，HTTP 契约归 architecture，开发和接入操作归 guides，部署恢复归 deployment，历史与上游来源归 reference，稳定规则归 rules。

只有读者操作、外部接入、部署步骤或必要理解发生变化时，更新已有对应入口。内部实现、重构和测试变化不默认修改文档或 PRD；review 不因缺少代码事实的文字副本要求补写。新增文档必须有现有入口无法承载的长期读者需求。

类型、字段全集、常量、依赖版本、迁移清单及测试枚举由代码、配置、schema 或现有生成物持有；文档链接其 owner，保留必要语义与最小操作示例，不维护手写镜像。需求与验收编号稳定，不因尚未实现而删除需求。

长期入口使用稳定名称，必要理由与取舍写在对应契约或操作说明中，不单列 ADR。修改、合并或删除文档时同步导航。历史决定通过 Git 追溯，不保留失效操作手册充当兼容入口。

评审、实施流水和逐次验证结果归对应 PR；完整输出按需要保存在实际可访问的 CI 制品或归档。源码树保留测试和必要夹具，不保存生成报告、配置副本或清理台账；本地临时路径不冒充持久归档。已提交旧记录通过 Git 历史追溯，历史通过不作为当前版本验收结果。

需求目标、设计决定、历史实现、当前实现和实际验证结果分别表达。来源保留具体路径或公开 URL、许可证与证据限制；本地排除材料说明恢复方法，不整体搬入 reference。
